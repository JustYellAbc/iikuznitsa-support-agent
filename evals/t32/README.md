# Т32. Локальный чат с моделью через OpenCode Go

Рабочий обработчик T04 принимает сообщение покупателя. Модель получает навыки T35, последние восемь сообщений покупателя и агента, а также прежний выбор товара. Она может искать по названию или потребности, читать точную карточку и обращаться к опубликованным ответам менеджеров и справке магазина. Сервер сверяет артикулы и условия, подставляет цену и ссылки из найденных записей. Явная просьба об операторе, тендер и выпуск документов используют действующие сервисы проекта. В трассе сохраняются модель, инструменты, источники, токены и задержка.

## Первый замер для Т30

27 ноября 2026 года. Одинаковый снимок каталога и одна сборка. Для каждой модели выполнены два круга по семи открытым синтетическим обращениям. В каждом круге проверены цена по SKU, восстановление пароля, цена по запросу, первоначальный выбор MDaemon, смена с 20 на 5 мест, передача тендера с обновлённым SKU и чтение только что опубликованного менеджером ответа новым покупателем. Проверка цены сверяет SKU и сумму. Для передачи сравниваются и причина, и карточка менеджера.

Задержка измерена от отправки действия T04 до регистрации видимого покупателю сообщения. Для каждого значения скорости взяты 12 ходов с моделью, включая неудачные. Обязательная передача тендера выполнялась сервером за 0,01–0,07 с. Модели проверялись одновременно в отдельных процессах. В одном диалоге Hy4 исчерпала лимит вывода при первоначальном подборе, поэтому два следующих шага также провалили проверку актуального SKU. Все 42 наблюдения, состав инструментов и исходы доступны в [observations.jsonl](observations.jsonl). По этим результатам команда выбрала Flash для демо. Итоговый замер качества на более широкой выборке входит в T34. [Решение T30](../../docs/t30-model-choice.md)

Отдельный прогон виджета в Edge проверил публикацию менеджера, открытие статьи по локальной ссылке и получение в том же чате цены SKU 61557. Время до появления ссылки на статью составило 3,94 с, до карточки товара при следующем запросе — 7,42 с.

## Повторить в WSL

Из корня этой рабочей копии, в окружении с зависимостями проекта и действующей авторизацией OpenCode Go. В каталоге данных нужен индекс T31 в `private/catalog.sqlite3`. Локальный скрипт получает ключ из текущей сессии OpenCode, передаёт его процессу и слушает только loopback.

```bash
export PYTHONPATH=backend:.
python evals/t32/local.py --model qwen3.8-flash --port 8332 --data-dir "$HOME/.local/state/softline-t32/qwen3.8-flash"
```

Чат находится по пути `/chat/`, кабинет — `/manager/`. Из другого терминала с тем же Python прогоняется `python evals/t32/compare.py --port 8332 --data-dir "$HOME/.local/state/softline-t32/qwen3.8-flash"`. Для седьмого сценария передайте одинаковый `OPERATOR_PASSWORD` серверу и проверке и добавьте `--published`. Флаг создаёт и публикует синтетическую статью через кабинетный API. Для уже запущенных здесь экземпляров пароль менеджера хранится в файле `manager.password` в приватном локальном каталоге соответствующей модели.

Для обычного запуска сервиса модель и адрес настраиваются через `AGENT_ENGINE=tools`, `MOCK_LLM=false`, `MODEL_SMART`, `LLM_BASE_URL` и `LLM_API_KEY`. В локальном Go-профиле цена дополнительного токена в журнале выставлена в ноль для сравнения внутри подписки. Для T19 отдельно учитываются подписка, фактические расходы и условия модели на сдаваемом стенде. OpenCode описывает Go как тариф для coding-agent трафика. Здесь проверен персональный локальный режим разработки. [Условия подключения](https://opencode.ai/docs/console/go/#where-can-i-use-it)
