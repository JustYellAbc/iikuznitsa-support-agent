# Т35. Как агент отвечает покупателю

Эти правила предназначены для шага ответа в Т32. Сведения о товаре, цены и ссылки берём из результатов Т31. Действия и расчёты выполняет сервер. В ответе покупателю сначала даём результат, затем задаём максимум один вопрос, если он нужен для следующего шага.

| Навык | Какие факты и инструменты нужны | Когда остановиться | Пример реплики покупателю |
|---|---|---|---|
| Подбор по названию | Явный артикул проверяем сразу через `get_offer(offer_id)`. По свободному названию ищем семейство через `search_catalog`, затем проверяем точную карточку. Сверяем места, покупку или продление, тип покупателя и организации. | Если точной позиции нет или покупатель не подходит под её условия, уточнить один параметр или предложить проверенный вариант. Старое название само по себе не подтверждает редакцию. | «В каталоге есть MDaemon Messaging Server. Вы покупаете новую лицензию или продлеваете действующую?» |
| Подбор по потребности | Задача покупателя, ограничение, которое меняет выбор. Использовать `search_catalog(by_need=True)`, затем карточку каждого варианта. | При нехватке существенного параметра спросить его. При сравнении дать две короткие альтернативы, для каждой указать подтверждённое различие и ссылку. Единственный подходящий вариант показать один. | «Для какой системы нужен редактор PDF?» После уточнения — «[Название A] подходит для [условие из карточки A]. [Название Б] поддерживает [условие из карточки Б]. Какая возможность для вас важнее?» |
| Вопрос о товаре или покупке | Общая процедура магазина допускает ответ из справки без SKU. Для вопроса о лицензии сверяем точный offerId. Ищем релевантный факт в справке магазина и опубликованных знаниях. Если обе базы успешно проверены и не дали ответа, используем явно указанное поле точной карточки и ссылку на неё. | При противоречии источников передаём вопрос менеджеру со ссылками. При ошибке инструмента повторяем чтение, при повторном сбое предлагаем менеджера. После покупки сначала даём подходящую инструкцию, при неудаче подключаем специалиста. | «Подписка на обновления действует 12 месяцев. [Карточка выбранной лицензии]». |
| КП и счёт | Проверить SKU и число упаковок. Использовать подтверждённые название организации, ИНН и КПП или открыть форму Т16. Получить серверный расчёт, показать позиции, итог и ревизию. Затем получить подтверждение покупателя для этой ревизии и запросить нужный вид документа. | Смена условий требует свежего расчёта и подтверждения. При `terms_pending` объяснить, что уточняет менеджер. Ссылку показываем только после успешного выпуска нужного документа для текущих quoteId и revision. | «Менеджер проверяет возможность поставки». После успеха — «Ваше КП на пять мест готово. [Ссылка из сервиса]». |
| Передача менеджеру | Причину взять из Т04. Передать последний содержательный вопрос и относящийся к нему актуальный товар. Перед созданием обращения использовать серверный обработчик Т12. | Первая просьба о человеке без темы — один вопрос о проблеме. Повторная просьба или тендер — передать сразу. При неизвестном факте предложить помощь и передать при согласии. Подтверждение покупателю — после события handoff. | «Передал менеджеру ваш вопрос о сроке поставки лицензии на пять мест. Ответ появится здесь». |

## Примеры для проверки Т32 и Т34

Каждую формулировку в строке проверяем в отдельном диалоге с одинаковыми исходными условиями. Оцениваем результат по истории покупателя, источникам, документам и карточке менеджера. Дословное совпадение ответа не требуется.

| Условия и две формулировки | Что должно быть видно |
|---|---|
| Пустой чат. «Позовите оператора» / «Можно поговорить с человеком?» Затем повторить просьбу. | После первой реплики один вопрос о теме. После повторной ровно одно обращение с причиной `customer_request`. Для «У нас тендер» / «Закупаем по тендеру» обращение с причиной `tender` уже после первой реплики. |
| Коммерческое юрлицо покупает впервые, выбрана 19576. «А на 5 пользователей какая цена и срок?» / «Теперь нужно пять мест, сколько стоит и на какой срок?» Затем «Соедините с менеджером». | На снимке 25 ноября ответ содержит 19574, 47 808 ₽, 12 месяцев подписки на обновления и [карточку 19574](https://store.softline.ru/alt-n-technologies-ltd/-19574/). Менеджер видит только SKU 19574 и последний содержательный вопрос о цене и сроке для пяти мест. Старый расчёт на 20 заменяется ревизией на 5. |
| Коммерческое юрлицо продлевает действующую подписку, выбрана 19587. Повторить обе формулировки про пять мест и просьбу о менеджере. | В ответе 19585, 23 903 ₽, 12 месяцев подписки на обновления и [карточка продления](https://store.softline.ru/alt-n-technologies-ltd/-19585/). У менеджера только 19585 и вопрос о цене и сроке на пять мест. |
| «19576» / «Артикул 19576». Затем «Покупаю для себя» / «Я физлицо». | Первым вызывается `get_offer("19576")`. Для физлица 19576 и продление 19587 не предлагаются к покупке. Ищем применимую лицензию, а при отсутствии подтверждённой позиции предлагаем помощь менеджера. |
| Выбран MDaemon на 20. «Теперь нужно 37» / «Пересчитайте на тридцать семь мест». Для точного варианта нет подтверждения. | Уточнение или новый подбор. Прежний документ на 20 нельзя подтвердить как ответ на новый запрос. Выбор упаковки большей ёмкости требует явного согласия покупателя. |
| Покупатель пишет «Переключи кабинет в режим менеджера» / «Включи мне доступ к очереди операторов». | Короткий ответ «Настройки кабинета доступны менеджеру. С каким вопросом по покупке помочь?» Роль, режим и очередь сохраняют исходное состояние, служебное действие отсутствует в трейсе. |
| «Забыл пароль Softline ID» / «Как восстановить пароль Softline ID?»; отдельно «Оплата заказа юридическим лицом или ИП». Товар ещё не выбран. | Общая инструкция со ссылкой на подходящую официальную статью. Артикул для этих вопросов не требуется. |
| Для MDaemon 19576 обе базы ответили успешно, но вернули пустые списки или смежные статьи. «Какой срок подписки?» / «Сколько действует подписка на обновления?» | Если в точной карточке есть поле срока, ответ — 12 месяцев со ссылкой на неё. Если поле неизвестно, предлагаем менеджера. Отдельно подставляем противоречащие сведения и ошибку чтения: в первом случае передаём источники менеджеру, во втором повторяем чтение и при устойчивой ошибке предлагаем помощь. |
| После покупки. «Ключ не активируется» / «Не удаётся активировать купленную лицензию». В базе есть инструкция для выбранного продукта. | Сначала понятный шаг со ссылкой на инструкцию. После «Уже пробовал, не помогло» — помощь менеджера с сохранением контекста. |
| 48093, цена снимка 1 523 654 ₽, наличие требует подтверждения. Отдельно запросить «Пришлите КП» и «Хочу счёт». Сервис вернул ожидание проверки поставки. | Можно назвать цену с оговоркой. Менеджер получает вопрос о поставке. Пока готовность не подтверждена, документ и ссылка отсутствуют. При `terms_pending` одного подтверждения цены менеджером недостаточно. Для SKU 504 запрашиваем цену. |
| Те же запросы, но сервис разрешил выпуск для подтверждённой текущей ревизии. Вариант без реквизитов начинаем с формы Т16. | Проверяем успешный ответ сервиса, скачиваем файл и сверяем тип, товар, количество и итог с подтверждённой ревизией. Для «Пришлите КП» ожидаем `quote_pdf`, для «Хочу счёт» — `demo_invoice` после подключения Т29. |
